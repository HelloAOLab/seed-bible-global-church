# ADR-0001: Only `packages/seed-bible-ap` changes in this repository

**Status:** accepted (2026-10-21)

## Context

The repository hosts the live CasualOS-based reader (`packages/seed-bible`), its extensions, 3D patterns, and shared tooling. The agenticprimitives rebuild must proceed without destabilising that app, and its history must be easy to review as one folder.

## Decision

All work for the rebuild lives under `packages/seed-bible-ap/`. No other path in this repository is edited for it: not `packages/seed-bible`, not `packages/*-extension`, not `patterns/`, not root configs, CI, `.cursor/`, or `CLAUDE.md`.

Existing packages are read-only sources. Code is ported by copying into this folder and rewriting against `ReaderBackend`; nothing here imports `@casual-simulation/*` or `packages/seed-bible/**`.

Permitted side effects: root `pnpm-lock.yaml`, regenerated by `pnpm install` when this package's `package.json`
changes; and three one-line **exclusions** that teach the root tooling to leave this folder alone (recorded
2026-10-22, reviewed with the owner): `tsconfig.json` excludes `packages/seed-bible-ap` (the folder has its own
typecheck), `eslint.config.mts` ignores `packages/seed-bible-ap/**` (its own lint), and `pnpm-workspace.yaml`
sets `core-js-pure: false` under `allowBuilds` (pnpm's own placeholder for a dependency this folder's Workers pull
in). Nothing else at the root is touched; an exclusion is the only kind of root edit this rule allows.

Out of scope of the rule: `~/skills` (the `seed` domain), ap-home, ap-town, ap-federation, and pokernight are separate repositories.

## Consequences

- This folder stays **one** pnpm workspace package. Shared code is `lib/` + tsconfig `paths`, not nested packages (would need a root `pnpm-workspace.yaml` edit).
- Locale files are copied (`scripts/port-locales.mjs`), not shared with `packages/seed-bible`.
- Extensions are ported as intent emitters inside `apps/reader-web/src/extensions/`, not imported from `packages/*-extension`.
- Root lint/format/test configs do not know about this folder's extra tooling; this package carries its own `vitest.config.ts` and scripts.
